# DW2 workflow adapted to Digimon Rumble Arena

The DW2 author's useful pattern is a green all-assembly baseline, a small per-function brief, a seed, one hypothesis per compile, durable diff notes, a bounded search, and a final full linked gate. DRA retains that discipline while testing its own compiler families, source boundaries, C++ ABI, and data layout. DW2's proposed GCC/ASPSX settings are comparison hypotheses, not DRA defaults. A byte-identical range under the current slot profile is experimental evidence until its plausible original object and uniform settings are reviewed. [DRA codegen model](CODEGEN_MODEL.md), [upstream matching-criteria discussion](https://github.com/Wyrelade/Digimon-World-2-Decomp/issues/5).

## Current local sequence

1. Resume from `PLAN.md` and a verified checkpoint; inspect `docs/CODEGEN_MODEL.md`. Search the journal for the **specific diff symptom**, for example `python tools/learning_search.py "delay slot compiler" --limit 3`. The search ranks independent findings; it does not choose a compiler for you.
2. Prepare a focused target with `python tools/decomp_session.py brief game:func_80000000 --m2c` or `--seed analysis/path/to/candidate.c`. Use a real manifest function in place of the example. The tool writes `analysis/scratch/<unit>/<function>/BRIEF.md`, a complete retail `target.s`, profile details, nearby matches, and optional seed/m2c output. Review ABI, fields, object lifetime, boundaries, and arithmetic before editing source.
3. Probe one hypothesis with `python tools/decomp_session.py probe game:func_80000000 --hypothesis "32-bit unsigned wrap before signed division"`. It reserves the attempt, runs the private slot probe, and records `RESULT.md`, `session.json`, and a diff report. Record the result after **each** attempt. A function-byte score or private whole-slot match is diagnostic until tables, aliases, placements, and the full gate agree.
4. Stop the manual cycle near ten probes. Keep the failed readable draft and reason. A new learning may reopen it with `python tools/decomp_session.py requeue game:func_80000000 --evidence docs/DECOMPILATION_LEARNINGS.md --reason "new field-width evidence"`. Alternatively, after logic/type review, try a bounded, calibrated local CPU permutation of equivalent natural source. Do not let a search mutate source contracts to improve a score.
5. For parallel work, `python tools/worker_workspace.py prepare worker_name --checkpoint analysis/checkpoints/<verified-id>` makes a hash-checked isolated snapshot. It is not a Git checkout and does not integrate changes. Use distinct names and private probe paths; return the candidate, diff, source hash, and `RESULT.md` to the parent. The parent integrates one coherent transaction and runs complete byte, section, alias, and placement verification across all fourteen outputs.

`python tools/profile_audit.py --summary` prints bounded counts; `--save` refreshes `config/us/compiler_profiles.json`. The inventory separates current per-slot `cc1`/`maspsx`/assembler flags, source counts, and address span from original-object provenance, which defaults to **unreviewed**. Single-function compiler isolations are boundary-review prompts, not invalidation or approval. Manual reviewed provenance requires explicit evidence. Neither comments nor byte matches confer it automatically.

After a fresh verified progress report and matching checkpoint, the parent may run `python tools/update_workflow.py --check` or `--save` to refresh README metrics and the difficult-function queue. It refuses stale progress. Workers do not use it to claim credit. SDK functions remain symbolized assembly and outside game-source counts.

When new evidence changes the effective whole-slot reproduction profile, use `requeue ... --refresh-profile` with that evidence. It retains old probes and rejects changed retail bytes, boundaries or calibration identity. The probe guard requires a real source definition before reserving an attempt: compiling retained assembly after a failed edit is an invalid source candidate, even if the diagnostic reports zero differences. Such records retain the raw report but are excluded from best-score summaries.

Read callee access widths even for apparently dead values. In two recent constructor drafts, the callee read an unwritten fourth stack word and discarded it downstream; neither private exact draft earned source credit. Likewise, removing legacy register constraints requires an arithmetic and caller-domain audit. Model negative halfword interpretation and word wrapping explicitly, re-probe every sibling, and fix incompatible shared declarations before the complete gate.

## Calibrated search and platform boundary

`.venv-permuter/Scripts/python.exe tools/calibrate_permuter.py` calibrated the local scorer against **three** known cases: leaf, branch, and jump-table-bearing function. All three had zero code score with exact linked code, and intentional register/opcode/branch changes scored worse. The jump table's bytes, 21 relocations, and linker placement passed a **separate** check; the code score cannot see that data. [Calibration record](../analysis/us/workflow/permuter_calibration/report.json). This is a scoring diagnostic, not a source-acceptance gate. No overnight search, distributed run, or auto-landing is implemented by this workflow.

The current canonical toolchain and complete gate are Windows-oriented, with the shipped default `bin/windows/gcc-psx/CC1PSX.EXE` and explicit slot overrides. The older small WSL analysis and a separate Linux GCC 2.95.2 private probe exist, but a Linux-native WSL batch/canonical build path is proposed work, not an implemented replacement for the Windows gate. Keep Linux experiments private and compare their exact compiler/flags to the Windows linked result. [Build configuration](../tools/build_dra.py), [completion plan](DECOMPILATION_PLAN.md).

`tools/permuter_batch.py` now supports a bounded private native search. First use `--debug` with `UNIT:FUNCTION=SEED_PATH` to confirm its own compiler reproduces the independently measured baseline and all existing source siblings. `--run --timeout 60 --jobs 2 --max-iterations 200` sets a time budget and observed-iteration stopping threshold; a few in-flight iterations can finish as concurrent workers stop. The default is a ten-iteration smoke. Reports record actual time/count and remain in `analysis/us/workflow/permuter_batch/`. The installed parser supports C; C++ slots are rejected. Correct-logic seeds still need explicit ABI/type review, and a winner requires source/relocation/data review and the complete gate. [Runner usage and evidence](../analysis/us/workflow/permuter_batch/README.md).

The real `analysis/workers/workflow_smoke` snapshot generated a brief and m2c output, searched its copied journal and reproduced the known 604-byte controller body with zero instruction differences. A subsequent two-job CPU search tried 202 observed permutations in 34.7 seconds with no improved B0DC0 candidate; canonical assembly remains. [Adoption evidence](../analysis/us/workflow/adoption.json).

The source policy is ordinary, defined C in C slots and genuine C++ in opted-in C++ slots. No target-guided assembly edits/postprocessing, register pins, fake arguments, uninitialized-value tricks, or undefined signed overflow. A private match, a calibrated score of zero, and a verified linked source swap are distinct evidence levels; original-object provenance needs another review beyond all three.
