# Digimon Rumble Arena code-generation model

This is a working model for the USA build, not a claim to have recovered the original build system. A byte-identical candidate establishes what **our current pipeline** emits. It does not, by itself, establish the original source, object boundaries, compiler revision, or flags. The sector-derived `src/<module>/<slot>.c` files are convenient link/layout slots; they are not proven original translation units. Compiler profiles isolated to short ranges, including a single function, remain experimental byte-match evidence until a plausible original-object grouping and uniform settings are established. The current source percentage is provisional for the same reason. [Build configuration](../tools/build_dra.py), [completion plan](DECOMPILATION_PLAN.md), [upstream matching-criteria discussion](https://github.com/Wyrelade/Digimon-World-2-Decomp/issues/5).

## Known pipeline and competing compiler families

The C pipeline preprocesses a source slot, invokes a PSX `cc1`, runs `maspsx`, assembles, and links it beside retained assembly. The baseline flags include `-O2 -mips1 -mcpu=3000 -funsigned-char -G0`; the build has explicitly recorded overrides for `-G`, compiler, extra `cc1` flags, and assembler version. These are **current reproduction settings**, not a universal recipe for retail DRA. Read the effective settings in `tools/build_dra.py` for the specific slot before probing. [Pipeline and flags](../tools/build_dra.py).

| Family | Current use | What the evidence establishes |
| --- | --- | --- |
| Shipped GCC 2.8.1 PSX | Current Windows default `cc1` (`bin/windows/gcc-psx/CC1PSX.EXE`) | Many ranges reproduce retail bytes with it; it is the default candidate, not a proven global compiler. `build_dra.py` also names a Linux path that is not present in the current Windows-visible tree. |
| PsyQ 4.6 `CC1PSX.EXE` | Explicit slot/range overrides | Some scheduling, delay slots, and address materialization match only with this family in private/complete comparisons; for example `title/E6AC.c` and `game/E324.c` have documented whole-slot gains. This remains evidence about generated code, not proof of original object provenance. |
| ESA/PsyQ 4.5 `CC1PSX.EXE` | Explicit overrides such as `title/12AF0.c` and `game/4CF7C.c` | A distinct egcs-era code-generation family makes these ranges match without sibling regressions in recorded comparisons. It must be tested on the proposed whole original object. |
| Native C++ PSY-Q frontend | `UNIT_CXX` slots use `CC1PLPSX.EXE` (g++ 2.95.2 family) and C++ preprocessing | Constructors, virtual dispatch, and destructors may need genuine C++ source/ABI. A `.c` extension is retained for layout; it does not imply C compilation in these slots. Exported C helpers retain C linkage. |

The build also has a GCC 2.7.2 candidate for select ranges. Do not infer one revision from a single register or delay-slot difference. Keep the exact compiler binary, full flag set (including `-G`, optimization, and assembler version), slot/range, and sibling results with every claim. DW2's proposed GCC 2.8.0/2.8.1 and ASPSX settings are useful comparison hypotheses, not inherited DRA facts. [Compiler/profile map](../tools/build_dra.py), [upstream criteria](https://github.com/Wyrelade/Digimon-World-2-Decomp/issues/5).

## Working loop

1. Start from a recorded all-assembly/mixed-source checkpoint that passes every complete output byte comparison and symbol/section placement check. The [2026-10-08 18:28 UTC checkpoint](../analysis/checkpoints/20261008T182817Z/checkpoint.json) records 14 complete comparisons and 3,349 input fingerprints; it is a baseline, not a timeless current state.
2. Inspect the entire retail routine, direct callers/callees, adjacent labels, data references, and the effective profile. Record real argument/return use and field widths before writing source. Keep a small scratch brief: expected boundary, source hypothesis, profile, diff symptom, and next hypothesis.
3. Write ordinary, defined C for C slots; use genuine C++ only where the slot's native C++ ABI requires it. Preserve observable call order, pointer widths, byte/halfword/word accesses, and 32-bit wrap. Retain SDK routines as symbolized assembly under the [SDK policy](SDK_POLICY.md).
4. Probe privately with the exact slot pipeline. Change one source hypothesis at a time. A local function-byte match is diagnostic: check every existing C body in that slot, then emitted `.rodata`/jump tables, internal aliases, section order, and placement. Save readable failed drafts and compiler/diff evidence; stop an unproductive search rather than embedding a code-generation trick.
5. After writers freeze, accept a source swap only through a fresh complete linked comparison of the executable and all overlays plus placement checks. Record hashes and test results. A private match alone does not earn complete-build source credit.

When a **cluster** of otherwise plausible bodies has the same scheduling or delay-slot symptom, compare compiler families and flags across the whole plausible object. A narrow profile override can document an experiment and preserve current bytes, but it is not certification that retail used a per-function setting. Prefer regrouping and revisiting original-object boundaries over accumulating arbitrary exceptions. `-G` changes address materialization and can affect `INCLUDE_ASM` ordering; jump tables can add or move data even when function bytes match. [Build implementation](../tools/build_dra.py), [learnings](DECOMPILATION_LEARNINGS.md).

## Source and evidence rules

Global declarations affect code generation as well as type safety. A `-G8` scalar declaration of a field alias can incorrectly invite small-data addressing for a large runtime object; preserve the audited enclosing object size. VFS state now has one shared declaration across three slots, with callback and user fields established by dispatch consumers. Changing a pointer-returning allocator to an integer declaration merely because both fit a PS1 register leaves incompatible C interfaces; use the real return type and re-probe every sibling. [Wave-seven contracts](../analysis/us/main/wave7_vfs_contract_audit.json), [gameplay allocator review](../analysis/us/game/wave7_cb518_cc240_contract_audit.json).

- No assembly postprocessing against target bytes, inline assembly, register constraints/pins, fake extra arguments, variadic declarations used solely to keep a register live, uninitialized reads, or undefined signed overflow to force a match. A match that needs one of these is an unresolved candidate, not recovered natural source. Legacy assisted bodies remain visible for review; this model does not silently certify them.
- A signature comes from the callee's actual register use and direct callers, not from the values incidentally present at a call site. A label inside a live frame or delay slot is an alias until independent-entry evidence says otherwise. Data rendered as instructions is still data when references and control flow establish that role.
- Describe evidence at its actual level: **draft**, **private function**, **private whole slot**, **complete linked checkpoint**, then **plausible original-object profile**. The latter needs a separate provenance audit and cannot be inferred merely from the first four.
- Keep game progress separate from symbolized SDK, assisted source, and unreviewed inventory. Reclassification can change the denominator without creating source. Byte matching and readable interfaces are distinct from relocation-safe modified/runtime builds. [Completion plan](DECOMPILATION_PLAN.md), [SDK policy](SDK_POLICY.md).
