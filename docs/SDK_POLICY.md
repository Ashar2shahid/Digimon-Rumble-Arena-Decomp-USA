# PsyQ and game-code scope

The user requested a complete matching decompilation of Digimon Rumble Arena's game code, with PsyQ retained as assembly. SDK code may contain handwritten routines. Reconstructing it as C to improve a percentage is outside this project's source-recovery objective.

The imported library inventory identifies the resident SDK block at `0x8003DEEC` through `0x8005EE1C` in the correctly extracted logical executable. Its evidence includes PsyQ library-object comparisons and SDK version strings. The current manifest has **633 entries** in that span: 365 `func`, 220 `asm`, and 48 `data`. These counts come from the current files; the older inventory's 676-entry summary is stale. The handwritten startup entry `func_8003DD50` is separately retained as assembly, giving 634 excluded manifest entries. Earlier game code around `0x80037458`–`0x8003A010` must remain in the game inventory; the old library report explicitly withdraws its previous SDK classification there.

`config/us/psyq_funcs.txt` records every excluded entry with its module and manifest kind. An SDK data or assembly entry is not treated as an uncompleted C function. The build still verifies every SDK byte and its placement as part of the complete executable.

The migration restored 133 old SDK C bodies to assembly derived from the retail logical image. Their branches, calls, and address loads retain symbols. Linker-owned padding stays in the linker layout. The exact-output gate verifies that this representation change preserves the executable. The SDK assembly remains local and ignored by Git, alongside disc-derived data; the original image and reference repository are unchanged.

The builder recognizes 35 resident slots containing only confirmed SDK assembly includes and inert declarations. It assembles those includes directly with GNU as in source order, preserving macro context and linker pad sections. An initializer, alias, unknown header/statement, or non-SDK include keeps the established C pipeline. Mixed movie/game source also keeps that pipeline. This reduces period-compiler involvement in SDK scaffolding without reconstructing or changing SDK implementations. The classification file is fingerprinted; classifier regression tests and the fresh complete 14-unit gate pass.

For modding, preserve SDK implementations and improve relocation information: exported entry points, data references, cross-section labels, hardware addresses, and pointers in tables. `tools/sdk_references.py --save` identifies symbolic references and potential literal RAM addresses for review. A clean retail comparison is a matching-build check; a movable layout additionally requires relocation checks, data-pointer reconstruction, and modified-build/runtime testing. We do not infer complete shiftability from a matching build or this static audit.

The movie overlay's SDK text was identified separately against the user's held PsyQ library archive. Three complete `LIBPRESS.LIB` module text windows match every non-relocated word: `LIBPRESS` at `0x80065270`–`0x80065900` (1,680 bytes, 306 checked words), `VLC_C` at `0x80065900`–`0x80065C80` (896 bytes, 212 checked words), and `BUILD` at `0x80065C80`–`0x80065D70` (240 bytes, 56 checked words). These windows cover 20 manifest text entries. Four old movie SDK C bodies were restored to assembly, and the complete movie output remains byte-identical. The library's presence in an archive labeled 4.7 does not alone establish an exclusive SDK version for the game.

`tools/identify_sdk.py` saves the matching windows, library archive hash, and parser limitations under `analysis/sdk-identification/`. Relocated words are excluded using actual LNK PATCH offsets, rather than masking every instruction immediate.

Separate full-byte comparisons identify movie SDK data without masking: LIBPRESS `.data` at `0x80065D74`–`0x80065EC4` (336 bytes), VLC_C `.data` at `0x80065EC4`–`0x80065EF4` (48 bytes), and BUILD `.data` at `0x80065EF4`–`0x80066D04` (3,600 bytes). LIBPRESS `.rdata` also matches the 80 bytes at `0x80064424`–`0x80064474`. None of these library sections has LNK patches. The manifest's misleadingly named `func_80065D74` is a single data fragment covering all three data sections; it is separately excluded as SDK data. `config/us/sdk_regions.json` records the exact evidence. The game state word at `0x80065D70` remains outside that SDK data range.

The SDK inventory now contains 655 manifest entries, including startup and the movie data fragment. Static reference inspection found 6,441 symbolic operands before adding this data fragment. Three literal movie table-address loads were replaced with paired `%hi`/`%lo` symbol references and passed the complete movie byte comparison. This is an improvement to relocation information, not proof that the entire project can move safely.
