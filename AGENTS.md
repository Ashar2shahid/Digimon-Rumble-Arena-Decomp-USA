# Decompilation agent workflow

At the start of each session, read `PLAN.md`, `docs/CODEGEN_MODEL.md`, and the relevant ranked findings from `python tools/learning_search.py "<observed diff or behavior>"`. Follow the user's latest instructions and file ownership. Use GPT-6.1 Sol (`gpt-6.1-sol`) with medium reasoning for decompilation and audit subagents, per the user's October 9 model correction. Keep PsyQ SDK routines symbolized in assembly; they are excluded from game-source credit.

For one assigned game function, use `python tools/decomp_session.py brief UNIT:func_XXXXXXXX --m2c` (or `--seed PATH`) to make a small `BRIEF.md` and a diagnostic seed. Inspect the complete retail body, caller/callee contracts, boundary, effective compiler profile, and adjacent matches. m2c output is a hypothesis, not source truth. Write natural, defined C, or genuine native C++ in an opted-in C++ slot. State one concrete source/codegen hypothesis per `python tools/decomp_session.py probe UNIT:func_XXXXXXXX --hypothesis "..."`; read `RESULT.md` and the private probe diff after every function attempt. Save readable failures.

The manual cycle caps at about ten probes. When it fails, preserve the seed and evidence. Requeue only for a new journal/profile/boundary finding with `decomp_session.py requeue ... --evidence PATH --reason "..."`, or run a bounded, locally calibrated CPU search after semantic review. A permuter score is diagnostic; emitted tables and linked placement require independent checks. Do not start overnight or distributed searches, or auto-land a score-zero candidate.

After an evidenced whole-slot profile change, `requeue ... --refresh-profile` may refresh compiler metadata while retaining old attempts. Retail identity, boundaries and calibration must remain unchanged; identical evidence does not reset the cap. Before reserving a probe, the session tool requires an actual source definition rather than retained `INCLUDE_ASM`. Invalid candidates are recorded separately and excluded from best-score accounting.

Review callee access width independently of downstream use: a fourth stack word read is still an uninitialized read even when the callee discards it later. Keep such private exact drafts unresolved. Removing existing register constraints also requires defined arithmetic and caller-domain review, followed by sibling/data checks and the complete linked gate. Repair shared ABI declarations in every affected consumer before accepting a build.

Workers use isolated checkpoint copies from `python tools/worker_workspace.py prepare NAME`, private output paths, and disjoint source ownership. The parent integrates one coherent function/object transaction at a time, including any reviewed boundary/data changes, then runs the complete executable plus thirteen-overlay byte and placement gate. Only that gate earns linked source credit. Record the source hash, effective compiler and flags, sibling results, emitted data, and any unresolved semantic limits.

Never change target assembly to force a result, postprocess emitted assembly against retail, pin registers, add fake arguments/varargs, rely on uninitialized reads or undefined signed overflow, or treat a per-function compiler override as certified original-object provenance. The current sector source slot is not established as an original translation unit. Use `python tools/profile_audit.py --summary` to see current reproduction profiles and pending boundary reviews; evidence of original object settings requires a separate, documented audit.

See [DW2 workflow adaptation](docs/DW2_WORKFLOW.md) for command scope and evidence levels. The parent owns shared profiles, headers, linker/config changes, `PLAN.md`, progress, and complete builds unless explicitly delegated.
